# 每个难度配置多种算法 + 增加随机性

## 总结

将原本"每个难度 = 单一固定算法"改为"每个难度 = 一个带权重的算法池"。每局开局时按权重随机抽取一个算法，整局使用同一算法。不同对局 AI 风格会有差异，从而增加随机性，同时保持各难度的整体强度梯度。

随机粒度：**每局开始选一个算法**（用户已确认）。AI 在一局内风格连贯，对局之间有变化。

## 现状分析

- [ai.js](file:///f:/CodeAi/ai-ide/game-xiangqi/js/ai.js) 是一个 IIFE 单例 `ChineseChessAI`，内部定义 5 个难度函数：
  - `getSimpleMove`（L565）= 随机+吃子偏好
  - `getEasyMove`（L586）= 单层贪心评估（已含 `Math.random()*5` 噪声）
  - `getMediumMove`（L634）= minimax 深度 2
  - `getHardMove`（L639）= minimax 深度 3
  - `getExpertMove`（L644）= minimax 深度 4
  - `minimax`（L650）已含 `shuffleArray` 打乱走法顺序（剪枝友好 + 一定平局随机性）
- [getMove](file:///f:/CodeAi/ai-ide/game-xiangqi/js/ai.js#L728-L745) 用 `switch(difficulty)` 硬分发到上述函数，并复制棋盘。
- [game.js#makeAIMove](file:///f:/CodeAi/ai-ide/game-xiangqi/js/game.js#L536-L550) 调用 `ChineseChessAI.getMove(this.board, this.aiDifficulty)`。
- [game.js#restart](file:///f:/CodeAi/ai-ide/game-xiangqi/js/game.js#L101-L131) 保存/恢复 `aiEnabled` 与 `aiDifficulty`，更新 AI 按钮/描述 UI。`toggleAI`（L133）与 `cycleDifficulty`（L138）都走 `restart()`。
- 公共导出（L780）：`getMove / Difficulty / getDifficultyName / getDifficultyDesc`。

约束：保持 `getMove(board, difficulty)` 签名不变，`game.js` 的 `makeAIMove` 无需改动；只需在 `restart()` 多调一次选算法。

## 设计

### 算法池配置（数据驱动）

新增 `DIFFICULTY_ALGORITHMS` 配置对象，键为难度 1-5，值为 `{ algo, weight }[]`。算法强度在同级内相近，保持难度的"手感"，但每局可能选到不同算法。

```
SIMPLE(1):  random 0.5      | randomCapture 0.5
EASY(2):    randomCapture 0.4 | greedy 0.6
MEDIUM(3):  greedy 0.3      | minimax2 0.7
HARD(4):    minimax2 0.3    | minimax3 0.7
EXPERT(5):  minimax3 0.35   | minimax4 0.65
```

### 算法注册表

新增 `ALGORITHM_REGISTRY`，name -> `(board) => move`：
- `random`：**新增**纯随机走法（从 `getSimpleMove` 中拆出随机分支）。
- `randomCapture`：即现有 `getSimpleMove`。
- `greedy`：即现有 `getEasyMove`。
- `minimax2` / `minimax3` / `minimax4`：即现有 `getMediumMove` / `getHardMove` / `getExpertMove`（不重命名，注册表引用即可）。

### 状态与选择

- 模块内新增私有变量 `currentAlgorithm = null`。
- 新增 `selectAlgorithm(difficulty)`：按权重从 `DIFFICULTY_ALGORITHMS[difficulty]` 随机抽一个 algo 名，写入 `currentAlgorithm` 并返回。`getMove` 首次调用时若 `currentAlgorithm` 为空则兜底调用一次。
- 新增 `weightedPick(pool)` 辅助函数（累加权重 + `Math.random()`）。

## 假设与决策

- **每局选一个算法**：用户确认。一局内 AI 风格连贯，跨局有随机差异。
- **算法池权重**：采用上表默认值，强度在同级内相近以保持难度梯度；权重集中在本级主力算法，避免越级（如大师级不会抽到 `random`）。
- **不改 `getMove` 签名、不改 HTML、不改 `makeAIMove`**：影响面最小。
- **不新增 UI 显示当前算法名**：用户未要求，避免范围蔓延（API 已暴露 `selectAlgorithm`，后续可按需展示）。
- **防御性兜底**：`currentAlgorithm` 为空时 `getMove` 自动调 `selectAlgorithm`；注册表未命中回退 `getEasyMove`。

## 验证步骤

1. 浏览器打开 `index.html`，开启 AI 对战。
2. 在同一难度（如中级）连续"重开"多局（点重开/反复切难度回到同一档），观察 AI 走法风格是否在不同局有差异（例如中级有时偏贪心吃子、有时偏深搜稳健）——验证多算法随机生效。
3. 各难度分别对弈一局，确认整体强度仍随难度递增（简单弱、大师强），未出现强度错位。
4. 切换难度后立即重开，确认 `selectAlgorithm` 被调用、新难度使用新池。
5. 控制台无报错；`getMove` 返回 null 时 `makeAIMove` 已有判空保护（L544），行为不变。
